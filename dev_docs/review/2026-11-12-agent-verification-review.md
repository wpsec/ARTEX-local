# Agent 复核流程评审

## 范围与处理结果

- 审查独立对话、planner/worker 的候选交接、提示词升级、调用契约和本地评测工具。
- 修复提示词首次播种与并发用户编辑之间的竞争：播种、默认升级和用户保存统一锁定 Agent 行，避免覆盖用户版本或争用版本号。
- 补充候选 fact ID 的交接与历史查询约定，降低复核意图滚出最近记录窗口后重复派发的可能性；复核仍依赖模型遵守提示词。
- 确认旧默认提示词精确匹配后才升级；自定义提示词、Agent 入口及 `report_finding` 参数结构保留。

## 未解决事项

- 真实模型的新旧对照暂缓。脚本模型测试只验证工具装配、候选 fact、意图血缘和结果写回，不能证明模型一定执行复核，也不能证明误报率改善。
- `report_finding.evidence` 仍是兼容性的可选字段，调用入口不会强制要求证据。模型或自定义提示词未遵守规则时，仍可能登记未充分验证的发现。
- 既有交付报告流程会将选中的原始请求和响应报文传入模型；报文可能包含敏感字段。同文件中的两个旧测试分别要求保留和隐藏这些字段，需要单独确定预期；本次未更改这一行为。
- `TestGraphOverviewExpandsAssociatedCompanyScope` 仍期待上游已删除的 `coverage.scope` 字段；这是既有测试与当前实现不一致，本次未恢复该字段。

## 验证

在相互隔离的临时 PostgreSQL 数据库中运行 Agent、数据库和 Server 包检查；Agent 和 Server 分别跳过上述一项独立复现的历史失败。靶场正负样本检查和 Go 静态检查单独运行。未向真实测试目标发起探测。
