# 【已完成】ARTEX 版本线修正评审

## 结论

当前版本应从原生 ARTEX 最后一个版本 `0.3.15` 递增为 `0.3.16`。本分支没有声明独立产品的 `2.x` 主版本，也没有记录足以支撑 `2.3.0` 跳号的兼容性断代；继续使用 `2.3.0` 会让用户误以为 ARTEX 已跨过上游多个版本线。

## 依据

- 本地 Git 历史在 `e6ec569` 将原生更新日志定版为 `0.3.15`。
- `7c8bab1` 新增 `VERSION` 与版本化镜像构建时写入 `2.3.0`，同期评审只解释了如何使用语义版本 tag，没有说明为何从 `0.3.15` 跳到 `2.3.0`。
- 该分支持续基于原生 ARTEX 代码迭代；保持原版本线有利于对照原生与衍生版本，也避免把工具版本或镜像构建标签误当成项目主版本。

## 修正

- 根目录 `VERSION`、Go fallback 版本、Web package version/lock 和 README 当前版本统一为 `0.3.16`。
- CHANGELOG 将此前 `2.3.0` 的功能记录归入 `0.3.16`，并解释版本线修正原因。
- Release workflow 接受 `v*` tag，并从 tag 写入二进制与 OCI 镜像版本，无需改 workflow。未来发布时使用 `v0.3.16`；本次没有创建 tag 或发布。
- 既有 `artex:2.3.0` 本地镜像属于旧构建记录。本次不重建、不启动或替换容器；下一次按 `VERSION` 构建将生成 `artex:0.3.16`。
- 历史开发文档中的 `2.3.0` 保留为当时构建事实；工具 ffuf `2.3.0` 与 ARTEX 项目版本无关。

## 验证

- 核对 `VERSION`、Go 默认版本、Web package 与 lock、README、CHANGELOG 的版本值一致。
- 核对安装脚本从 `VERSION` 初始化新安装默认值，`build.sh` 将版本注入二进制，Compose 将其用于本地镜像名和 OCI 标签。
- 核对 Release workflow 使用 tag 名，不存在硬编码 `2.3.0`。
