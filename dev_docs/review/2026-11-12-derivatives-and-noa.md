# ARTEX 衍生版本与 noa 上下文压缩评审

## 结论

- ARTEX 的分支版本差异很大，不建议按版本号追平或整分支合并。只挑选能对应本仓库明确缺口、且能保持现有 Agent 调用方式的独立能力。
- 值得继续评估的方向是审批失败时转人工、脚本审批快照、基于已捕获证据的请求重放，以及 finding 的机器可核验状态和反证记录。ARTEX 已有流量证据绑定、报告和复测流程，相关能力应先核对现有实现，避免重复建设。
- noa 的核心接入已经存在，但目前是默认关闭的实验能力，不应视为完成验证的正式默认功能。它有模型生成摘要和原文归档的设计，理论上可保留长任务上下文；当前没有真实模型效果对照，不能据代码或合成测试推断自主渗透效果提升。
- 本轮将 noa 归档目录收紧为当前运行用户私有权限，并让“删除任务文件”选项纳入对应的 noa 归档。归档仍是明文；独立对话归档跟随现有对话文件生命周期，本轮不改变对话删除行为。

## 评审范围与证据

检查本仓库 Agent、noa 设置、运行目录和调用链；查询 CodeGraph 的 `enableNoa` 调用关系；阅读本地缓存的 norma `v0.4.3` 的 `noaadapter` 实现；对照公开分支的版本记录和变更说明。外部 ARTEX 版本目录由独立维护的 artex.sh 指南汇总，该站声明不隶属于原作者或各分支；分支能力判断优先以对应仓库的 CHANGELOG 为准。

## 衍生版本能力筛选

| RuoJi6 v0.3.21 / v0.3.23：Judge 失败重试及限速；失败默认转人工 | 外部模型故障时避免静默放行，并限制裁判调用异常增长 | 高价值候选。当前仓库 Judge 默认失败动作仍为 `allow`，虽可配置 `ask`/`deny`；应独立评审默认值变化及兼容影响 |

| sharenjun v0.4.4：从已捕获流量建立请求重放工作区，发送前校验任务范围并固定 DNS | 让复测从已有证据出发，降低重放时目标漂移风险 | 可借鉴范围校验和 DNS 固定；本地已有流量关联与复测，先确认实际缺口后再决定实现 |
| AntiFox v2.0：把利用过程按步骤记录请求、响应、验证结论并关联真实流量，生成结构化报告 | 可能改善漏洞复现步骤和报告可读性 | 本仓库已有 finding、流量证据、复测和报告；只借鉴缺失的证据关联规则，不迁入整套报告平台、RAG 或多用户权限架构 |

## noa 当前实现

- `go.mod` 锁定 `github.com/Autumn-27/norma v0.4.3`。noa 在原 ARTEX v0.3.11 被列为基于 norma v0.4.0 的实验压缩机制；当前仓库通过 norma 包的 `noaadapter` 接入，并非把 norma 源码复制进 ARTEX。
- 作者在本仓库历史提交 `c457963` 明确将各 Agent 的归档从任务/会话工作目录改为统一的 `<workDir>/noa/<SessionID>`，提交说明是避免归档分散。设置页原先声称归档在任务工作目录，与实际设计不符；本轮已更正文案，没有改变归档布局。
- `noa_compaction` 设置默认关闭。Planner、Worker、主 Agent 和对话 Agent 每次新建 run 时读取开关；修改设置只影响之后启动的 run。
- `noaadapter.Enable` 将 Compactor、Compress 工具和提示词作为一个整体挂入 Agent。启用后清除原生 `Compaction`，避免两套上下文管理器并行；初始化失败时记录告警并保留原生压缩。
- noa 让模型按规则生成分层摘要，并把被压缩的原消息保存在 `<workDir>/noa/<sessionID>`，提示词提供归档检索路径。它能降低当前上下文占用，并为追溯完整原文保留通道；摘要仍由模型生成，可能遗漏或误述信息，也会增加压缩调用与摘要 token 成本。
- noa 接入新增针对性回归，覆盖默认关闭、Compactor/Compress/提示词装配、私有目录权限及初始化失败回退；尚未用真实模型验证摘要质量、上下文收益与长任务行为。上游模块包含自身测试，但不能替代 ARTEX 侧的真实模型评测。

### 隐私与生命周期

noaadapter 将归档和状态文件以 `0644` 写入，包含完整对话及工具输出。对单一 OS 用户是低风险，但在同机多账号、共享卷或备份环境中可能暴露任务内容。ARTEX 现将 `<workDir>/noa` 创建并强制设为 `0700`；若目录不可用，noa 启用失败并回退原生压缩。文件仍未加密，同一运行用户仍可读取。

归档保存在全局 workDir，不属于 PostgreSQL 事务或任务导出包。用户选中“删除任务文件”时，ARTEX 会与任务工作目录、transcript 一起暂存对应的 `exp<探索ID>-*` noa 归档；数据库删除失败时可回滚，未选中时这些文件按用户选择保留。对话 Agent 的 `chat-conv-<ID>` 归档仍随现有会话磁盘 transcript 保留；当前对话删除端点只删除数据库记录，本轮不改变该既有语义。noa 没有独立保留期限或清理命令。

## 本轮处理和未完成项

- 已将 noa 归档父目录限制为 `0700`；目录创建或权限设置失败时保留原生 compaction 并输出告警。
- 未改变 `noa_compaction` 默认关闭状态，未修改 norma 依赖版本。
- 未运行真实模型评测，按用户此前决定暂缓。尚未证明 noa 相比原生压缩能提高 Web/API 任务的漏洞检出、证据保留或任务完成率。
- 未实现归档加密、独立保留期限或清理命令；任务级显式删除已覆盖，独立对话归档遵从现有对话文件保留语义。
- 定向 Go 回归通过：noa 接入开关/归档权限/故障回退，以及任务文件与 noa 归档删除、精确匹配和失败回滚。改动 TSX 文件通过 Biome lint；Biome check 仍报告这些文件中三处未改动代码的既有格式差异。`git diff --check` 通过。
