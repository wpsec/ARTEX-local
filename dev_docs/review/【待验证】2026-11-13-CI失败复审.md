# 【待验证】CI 失败复审

## 结论

附件中的 CI 有两项失败：Go 测试在 `Manager.Close()` 关闭 PostgreSQL 后仍有任务后台循环写入；漏洞扫描发现 Go 1.26.10 标准库 `net/http` 存在 `GO-2026-6859`，Go 1.26.11 已修复。

## 修复与复核

- `Manager` 登记所属 `Server`，关停时先取消服务与 Agent 工作，再等待任务循环、已准入任务操作、归档器、日志持久化和服务后台工作结束；随后停止并等待资产补全 worker，最后关闭数据库。
- `jsonb_build_object` 的参数补充显式类型，避免 PostgreSQL 无法推断占位符类型。
- 交付报告中的请求/响应在交给报告生成器前脱敏认证头、Cookie、敏感查询参数及 JSON/form 字段；原始流量留存不变。
- 工具升级补充 `update_finding_report.evidence_version`，保留用户自定义 schema、描述和绑定。
- Agent 概览增加有界任务授权范围摘要，覆盖度关闭时仍保留范围与主机数；范围查询在数据库侧限量，并缓存重复公司范围。
- 关停等待日志持久化和资产补全 worker 退出后再关闭 PostgreSQL。
- Go 最低版本、CI 和 release 构建统一到 1.26.11；Go 测试包串行运行，避免多个包同时改写同一个测试数据库。

## 本地验证与待验证

- 使用空的临时 PostgreSQL 17 数据库，以 Go 1.27.1 串行运行所有 Git 跟踪 Go 包测试，通过；server 全量测试没有复现关库后的 planner/activity/task-archive 写入。
- 所有 Git 跟踪 Go 包的 `go vet -p 1` 通过。
- 之后追加的复审修正未重跑测试；当前 `go build ./agent ./db ./enrich ./server` 和对应 `go vet -p 1` 通过。
- 本机未安装 `govulncheck`；需由 GitHub Actions 在 Go 1.26.11 上重新运行漏洞扫描和完整 CI 后关闭本项。
- 本地工作区含 Git 忽略的 `data/tasks` 历史源码，因此本地测试显式列出跟踪包；CI 的干净 checkout 使用 `go test -p 1 ./...`。
