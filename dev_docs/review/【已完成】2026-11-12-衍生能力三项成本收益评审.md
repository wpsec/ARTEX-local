# 【已完成】衍生能力三项成本收益评审

## 结论

只保留两项有清晰净收益的工作：

1. Judge 仅在用户启用时运行。新配置默认在 Judge 故障时转人工；已有明确配置继续生效。瞬时错误最多重试一次，遵从 profile 的关闭开关与间隔设置，并受单次 Judge 总超时约束；不另造一套调用限额。
2. 为 finding 增加独立的证据引用核验结果，检查结构化引用是否能在已绑定的 proof/verification HTTP 原文中定位。它只说明证据可定位，不能把漏洞处置状态自动改为“已确认”。可附带可选反证说明。

当前不迁入脚本审批源码快照的完整实现。它的安全目标成立，但 ARTEX 当前由 Norma Bash 工具执行命令；要保证审批看到的源码就是最终执行的字节，需要解决命令解析、路径别名、间接加载和审批到执行之间的文件变化。只存路径、长度和哈希并不构成执行绑定。没有本地脚本调用数据证明这是高频风险前，不承担这组集成复杂度与源码进入模型上下文的成本。

## 逐项评审

### 审批快照绑定脚本内容

- **本地现状**：`intercept.Trace` 对工具名和 JSON 入参计算摘要并记录审查输入；这能识别被审批的工具入参，但不读取命令所引用脚本的源码。执行入口仍是 ARTEX 透传的原生 Bash 工具。
- **收益**：Judge 或人工审批能看到直接脚本的内容，降低只看 `python ./check.py` 这类调用字符串所产生的盲区。
- **成本与边界**：读文件和 SHA-256 本身开销很小；源码进入审批 prompt 会消耗上下文与 token。完整覆盖还要识别解释器、相对路径、软链接、`source`、生成后执行和复合 shell 命令。快照内容与哈希若不在执行端校验或执行不可变副本，只是审计记录，不能保证批准内容等于实际执行内容。
- **决定**：本轮不实现。若后续运行数据表明脚本式工具调用常见，再限定支持的直接脚本形式，并在实施前明确快照、审批和执行使用同一份内容的机制；不宣传为通用脚本执行保护。

### Judge 故障转人工、重试与限速

- **本地现状**：Judge 默认关闭，超时默认 15 秒，失败动作默认 `allow`，失败动作已有 `allow`、`ask`、`deny` 配置。Judge 回调当前只调用一次模型；任务主调用路径上的瞬时错误重试不会自动覆盖这个直调路径。profile 的 provider 被复用，并承载现有每 profile 请求限速。
- **收益**：Judge 被主动启用时，模型故障不再静默放行，能保留它作为命令审查兜底的预期。一次有界瞬时错误重试可降低短暂断流造成的人工打断。
- **性能与兼容性**：Judge 关闭时完全无影响。失败后 `ask` 会增加人工等待；现有审批等待上限为 300 秒，超时默认拒绝。一次重试只增加失败路径上的模型调用和退避延迟，必须受现有 15 秒 Judge 总超时约束。profile 已有限速，不应叠加独立 limiter。启用 Judge 但数据库没有保存失败动作的旧实例会从 `allow` 变成 `ask`，必须单独处理才能避免意外中断。
- **决定**：值得纳入开发。新配置的失败默认值改为 `ask`；保留已保存的显式 `allow`/`deny`，不覆写用户设置。兼容处理应只为升级前已启用 Judge 且没有失败动作记录的实例补存 `allow`；新安装及此前未启用的配置使用 `ask`。瞬时错误至多重试一次，尊重 profile 的关闭开关和已配间隔，次数封顶为一次；认证、额度耗尽、上下文过长及无效裁决不重试。默认值修改单独记录并回归 API、UI 初始值与旧设置兼容。

### Finding 机器可核验证据

- **本地现状**：finding triage 状态只描述处置；另有不可变 HTTP evidence snapshot、`baseline`/`proof`/`verification` 等绑定角色、证据版本和报告版本。现有结构没有独立记录“引用能否回到原始响应”的核验状态。
- **收益**：报告审阅者可快速确认关键引用是否来自绑定的原始流量，减少模型编造或错引响应内容的风险；反证说明也能保留失败尝试和与结论冲突的观察。
- **性能与边界**：无需新增模型调用。需要新增可选的结构化证据引用（绑定 ID、request/response 侧、原文片段），只核验已绑定的 proof/verification HTTP 证据；单侧读取上限建议 4 MiB，超限或无法解码时标记 `not_assessed`。`matched` 只证明引用文字存在；`unmatched` 也不等于漏洞为假，可能是引用错误或捕获不完整。不得仅凭模型写出的复测 verdict 自动升级。证据版本变化后旧核验结果必须失效。TCP 等非 HTTP finding 保持 `not_assessed`，不能因此拒绝登记 finding。
- **决定**：纳入轻量开发。新增 `evidence_check_status`，与 triage 状态分离，采用 `matched`、`unmatched`、`not_assessed` 等不暗示漏洞已确认的标签；界面使用“证据引用匹配”等准确文案。可选反证字段随 finding 一起保存，但缺失时不阻塞。首版不加 POE 等级：它不是引用匹配所必需，且与现有 severity 容易混淆；先等 ARTEX 定义出稳定、可复核的分级标准。
