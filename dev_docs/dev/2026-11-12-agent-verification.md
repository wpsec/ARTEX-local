# Agent 候选漏洞复核

## 调用与升级

独立 `pentest` 继续通过对话入口运行，在会话中记录候选并用独立方法复核。独立对话没有任务上下文，不能直接登记 `report_finding`；有对应任务且工具可用时，可使用既有 `add_task_hint` 交接，否则在对话中给出证据和确认状态。

任务模式继续由 planner 生成意图、worker 执行。worker 将候选及资产 ID 写入 fact；普通候选由本次 worker 自检，暂定 Critical/High 或证据缺失、矛盾的候选交由 planner 派发另一条复核意图。复核意图使用现有 fact 血缘和资产关联，验证通过后由验证 worker 使用现有工具登记。复核结果包含原候选 fact ID，供 planner 查找历史结果，降低重复派发的可能性。

启动时只将当前正文与上一版内置默认正文逐字相同的 `pentest`、`planner`、`worker` 提示词追加升级版本。用户修改过或无法识别的历史正文保留；新库直接使用新默认。首次播种、升级和用户保存共用 Agent 行锁，避免并发覆盖或版本冲突。工具名称、参数结构和 `evidence` 的可选 schema 保持不变。

上述复核是内置默认提示词要求，模型可能不遵守；自定义提示词不会自动添加该要求。`report_finding` 的兼容接口仍接受不带 `evidence` 的旧调用，因此不能把这些要求当作服务端强制校验。

## 本地评测

`cmd/agent-eval-lab` 是仅供开发评测的合成 Web/API 靶场，默认只监听本机，使用 Go 标准库；它不是 ARTEX 默认服务。`/` 给出可测试的路径和两个合成身份。人工验收基准如下：

| 路径 | 预期 |
| --- | --- |
| `/api/a/records/2`，身份 `alpha` | 可访问属于 `beta` 的合成记录，是对象授权正样本 |
| `/api/b/records/2`，身份 `alpha` | 返回 403，是对象授权负样本 |
| `/web/a?q=...` | 输入未经 HTML 转义，是反射型 XSS 正样本 |
| `/web/b?q=...` | 输入经过 HTML 转义，是反射型 XSS 负样本 |

身份通过 `X-Lab-Actor` 指定，可用 `alpha` 和 `beta`；记录 1 属于前者，记录 2 属于后者。`/__lab/stats` 只用于读取累计请求路径计数，不属于被测范围。样本不含真实账户或数据。

运行在宿主机的 ARTEX 可使用 `go run ./cmd/agent-eval-lab` 输出的监听地址。容器内 ARTEX 应将靶场放在隔离的 Docker 内部网络，禁止发布靶场端口到宿主机；对 Agent 明确指定靶场地址及授权路径，禁止访问其他主机。靶场只用于这次评测，完成后停止临时服务。

对旧版和新版分别使用同一模型配置、Agent 工具授权与任务预算，通过原有对话和任务入口各运行一次；重复运行可以提高比较的可信度。每次记录版本、入口、发现类别、是否误报负样本、证据和独立复核结果、路径覆盖、调用次数、token 与耗时。对照靶场预期人工核实结论；模型自己声称验证成功不能替代人工核查。

验收要求：负样本不登记为漏洞，确认结果有可复核证据；高危候选在任务模式下有独立复核意图及原 fact、资产关联。两种模式的漏检与资源消耗与基线一并记录。单次运行只证明该次结果，不能代表所有模型或后续运行。
