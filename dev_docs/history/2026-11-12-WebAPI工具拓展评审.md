# 【已完成评审；真实模型评测暂缓】Web/API 工具拓展评审

## 状态

工具镜像构建和隔离样本验证已完成，当前 ARTEX 容器已切换到 `artex:2.3.0`（镜像 ID `sha256:c947f79a73d68e22653dba2d26bf9cead74da13fb94a38c3b5b4b720736fc8a8`，Docker 报告大小 `1,240,919,299` bytes）。切换后 Web 根路径返回 HTTP 200，容器内确认 ffuf、sqlmap、Chromium 和 Puppeteer Core 可用；PostgreSQL 保持原容器并健康。真实模型选用工具的行为评测按用户决定暂缓。任务允许白名单配置后，资产绑定意图的范围外资产会被资产闸门拒绝；Bash/CLI 请求仍没有网络层范围强制校验，用户决定将此作为单用户本地部署的已知限制，不在本轮增加出口代理。

## 审查范围

审查 ffuf、sqlmap、Puppeteer Core/Chromium 的镜像构建与调用方式，Web/API Skills 的授权和证据约束，ZAP/Nuclei/Schemathesis 在同一类本地合成样本上的互补性，以及现有工具边界。所有动态扫描均指向隔离容器内的 loopback 合成靶场，未访问外部目标，也未读取真实凭据。

## 发现

### 已接受限制：CLI 工具没有网络层目标范围硬校验

`guard/guard.go` 明确记录 RoE 授权范围机制已移除；拦截规则未匹配且模型判定未接入时会放行。任务约束主要注入 Planner/Worker 提示词。若配置了任务允许白名单，ARTEX 会在创建资产绑定意图时通过 `CheckAssetsIntercept` 拦截不在允许范围内的资产；但未启用白名单时默认放行，且这不能阻止 Bash 中的 `curl`、ffuf、sqlmap 等命令访问任意 URL。

**处理状态**：用户决定按单用户本地部署的现有限制记录，本轮不增加网络出口代理。定向 Go 单元回归验证已配置任务白名单时范围外资产被 `EvaluateAssetGate` 拒绝、命中允许范围的目标放行；`addOneIntent` 对资产绑定会调用 `CheckAssetsIntercept`。这不是任意 Bash URL 的强制拦截；动态扫描只在 `network none` 容器内运行。

### 中：SQLMap `--batch` 仍可能自动扩大检测

仅指定 `--batch --risk=1 --level=1` 时，SQLMap 会对“是否追加高于指定 level/risk 的 DBMS 测试”使用批处理默认答案。此前本地运行因此发出 258 个请求，且没有确认注入。

**处理状态**：Web 测试 Skill 增加 `--answers='extending provided level=N'`，明确拒绝扩展；首轮参数固定为 `risk=1`、`level=1`、单线程和 30 秒限制。默认使用 `--skip-waf` 避免额外 WAF/IPS 启发式探测；此参数只关闭 SQLMap 的启发式识别，不会绕过目标防护，也意味着该次不评估 WAF。

### 低：定制过滤器脚本缺少场景证据

镜像保留完整 SQLMap 上游源码，当前固定版本的 `tamper/` 目录有 85 个脚本；本地样本没有证明需要 ARTEX 自维护通用绕过脚本。

**处理状态**：不新增项目自定义脚本、不默认调用或自动串联 `--tamper`。只有授权明确覆盖过滤器/WAF 测试且有具体请求/响应证据时，才先评估上游已有脚本；没有合适脚本再为单一已知转换编写脚本，并在隔离靶场用正负样本验证。脚本仍按需显式调用，不能由 Agent 根据拦截提示自动选择。

### 低：浏览器采集脚本需要目标专属配置

`runtime_harvest.js` 需要授权会话状态及目标响应门禁，不适合作为通用自动执行脚本。

**处理状态**：保留参考脚本定位，只补齐 Puppeteer Core 与 Chromium 运行依赖；不自动运行脚本。

### 认证后双身份测试

在隔离 loopback fixture 中分别使用 Alice、Bob 两个测试身份请求各自及对方的对象：故意存在 BOLA 的跨用户对象端点返回 200，安全控制端点和管理操作返回 403，匿名请求返回 401；ARTEX 流量记录捕获 16 条请求/响应记录。该流程说明现有 Browser/Bash/流量记录足以完成固定双身份对照，无需新增请求对比工具。测试证明了 fixture 与请求记录链路，不证明真实模型会自动设计或正确解释 BOLA 测试；真实模型评测按用户决定暂缓。

### ZAP Skill 可见性与调用边界

`web-app-penetration-testing` Skill 声明 ZAP MCP。ZAP MCP 客户端实际发现 17 个工具，并完成 Spider 与 Active Scan 调用。Agent 侧 `TestDeferredSystem_GatedNotInBlock` 验证 Skill 门控的工具名不会进入全局可见工具块；`TestUnlockGatingFlow` 验证共享 `UnlockSet` 在 Skill 解锁前后状态发生预期变化。`server/assembly.go` 将 Skill Registry 的 `OnInvoke` 接到该解锁回调，并返回解锁工具名。

持久回归 `server.TestWireAgentAugmentUnlocksSeededZAPAfterSkillLoad` 用隔离 PostgreSQL 调用真实 `server.wireAgentAugment`，将默认 `OWASP ZAP` seed 指向 loopback MCP fixture，检查工具未加载 Skill 时保持 deferred/locked，加载 `web-app-penetration-testing` 后解锁并恰好调用 fixture 一次。`agent.TestSkillGatedMCPCallThroughSession` 经过 `agent.AugmentTools`，再用 fake provider 驱动 `agentcore.NewSession`，不发生外部模型调用：初始模型工具 schema 不含 deferred MCP 工具，但包含 Skill、`SearchExtraTools` 和 `ExecuteExtraTool`；Skill 加载前的执行请求被拒绝；加载后工具名进入对话，schema 查询返回参数，执行请求到达 fixture MCP 工具。`db.TestBundledWebSkillsReferenceSeededZAPMCP` 同时检查两个 Skill 的 `mcps` 名称和 ZAP MCP seed 常量一致。结合单独对实际 ZAP MCP 的工具发现和扫描调用，这覆盖数据库装配、Skill 解锁、工具发现和调用；尚未在真实 ZAP 服务上跑完 Agent Session，也未评估真实模型会否选择这些步骤，真实模型评测按用户决定暂缓。

动态测试的 SQLMap、Nuclei、Schemathesis 和 API 样本都在断网临时容器运行。此前无任务时 `docker stats` 单点采样为 ARTEX `493.9 MiB`、PostgreSQL `778.9 MiB`；本轮容器切换后的无任务采样为 ARTEX `515.8 MiB`、PostgreSQL `773.2 MiB`。这些数值不代表整个使用周期的固定空闲基线。一次 ZAP 重复扫描后的临时容器采样为 `1.361 GiB`，该数值也不是可证明的峰值。本轮重建后的 `artex:2.3.0` 镜像 ID 为 `sha256:c947f79a73d68e22653dba2d26bf9cead74da13fb94a38c3b5b4b720736fc8a8`，Docker 报告大小为 `1,240,919,299` bytes；相较记录的拓展前基线增加 `36,505,465` bytes（约 34.8 MiB）。

新工具的临时运行资源在 `network none` 容器中用 cgroup `memory.peak` 记录，峰值包含工具、运行时和本地 fixture：ffuf 低速 33 项路径枚举为 `27.8 MiB`（fixture 基线 `18.7 MiB`）；SQLMap 对静态本地端点执行低强度单参数扫描为 `56.1 MiB`（fixture 基线 `18.5 MiB`，该次不用于漏洞判定）；Puppeteer Core 启动 Chromium 并打开本地 data 页面为 `215.2 MiB`（Node 基线 `22.2 MiB`）。这些是各自独立容器的单次峰值，工具结束后临时容器销毁；主 ARTEX 容器进程表只见 ARTEX、ZAP 和启动 shell，没有 ffuf/sqlmap 常驻进程。Nuclei/Schemathesis 候选评估使用 `/usr/bin/time` 记录的峰值 RSS 分别约为 `107–116 MiB` 与 `396–412 MiB`；均未打包进 ARTEX 镜像。
