# 【已完成】衍生能力轻量实现说明

## 范围与取舍

按三方成本收益评审实现 Judge 故障回退与 finding 证据引用。保留 ARTEX 原有 Agent、工具调用、授权范围及审批入口，不增加 agent 类型、服务、MCP、数据库角色或运行时模型调用。脚本审批源码快照和 POE 等级不纳入。

## Judge 故障处理

- 新配置缺少 `llm_judge_fail_action` 时默认 `ask`；Judge 仍默认关闭。
- 数据库升级时，仅为此前已启用 Judge 且没有保存失败动作的旧实例补存 `allow`，避免升级时改变其既有行为。已保存的 `allow`、`ask`、`deny` 不覆盖；新安装及此前未启用 Judge 的配置使用新默认值 `ask`。
- Judge 模型流式调用遇到可重试的瞬时错误时，最多重试一次。复用 profile 的重试间隔、请求限速和配置；不增加独立 limiter，也不重试认证/权限拒绝、额度耗尽、上下文过长等确定性错误。
- 整个调用及退避仍受现有 15 秒 Judge 超时约束。重试失败后沿用已有 `ask`/`deny`/`allow` 流程；新默认转人工，审批等待超时仍按原配置处理。

## Finding 原文引用与反证

- 在原有 finding 表和探索节点 payload 上增加证据核验状态、说明、结构化原文引用及可选反证，不改 triage 状态和 HTTP API 主流程。
- `report_finding` 可接收引用；报告 Agent 在已有流量绑定后也可通过 `update_finding_report` 补充引用或反证，兼容旧工具调用参数。绑定关闭时从 Agent 的 `report_finding` schema 隐藏流量引用相关参数；运行时仍忽略模型额外发送的这些字段。
- 引用必须指向该 finding 绑定的真实流量，且只在 `proof`/`verification` HTTP(S) 快照中核对请求或响应原文。匹配采用精确字节子串；单次最多检查 16 条引用，引用片段长度为 8–2048 个 Unicode 字符，单份正文和合计读取量均限制为 4 MiB。仅支持 identity、gzip、deflate 正文；超限、格式不支持或证据缺失均为未核验。
- `matched` 只表示引用原文可定位，`unmatched` 只表示至少一条引用未匹配；两者都不决定漏洞真假。没有引用或无法核验时为 `not_assessed`。非 HTTP finding 仍可正常登记。
- 绑定、改用途、排序或移除流量会增加证据版本并先重置核验状态；之后对现存引用重新检查。摘要与详情 API、JSON 和 Markdown 导出返回/呈现状态、说明、引用和反证；详情页及导出均明确说明“原文匹配不代表漏洞已确认”。
- 不读取新的目标、不重放请求、不增加 LLM 判断；检查只访问 ARTEX 已保存的不可变证据快照。
