## 发现与处理

### 高：原登录须知与 ARTEX 授权测试用途冲突

原文禁止所有线上目标测试，即使目标属于用户或已有授权，并禁止实际渗透测试。改为要求明确授权和范围确认，说明主动操作的影响及审批机制的边界。

### 高：原数据说明不符合可配置的数据流

原文声称所有数据均留在本机。更新为说明本地 PostgreSQL/数据目录的默认存储位置，并明确外部 LLM/MCP 可能接收提示词、工具参数和结果；补充管理端口和凭据保护说明。

### 中：Release 镜像缺少规范化版本 tag，镜像标签元数据会显示为 dev

增加 `2.3.0` 语义版本 tag，并将 Release tag 作为 Docker build arg 写入 OCI 版本标签。`build.sh` 会从 `VERSION` 读取默认二进制版本并去除 tag 的 `v` 前缀。

### 中：本地二进制版本可能与镜像 tag 不一致

README 使用 `VERSION` 同时传给 `ARTEX_BUILD_VERSION` 和 `ARTEX_VERSION`；本地 Compose 将其用于镜像名和 OCI 标签。安装脚本只在用户没有自定义版本值时从 `VERSION` 初始化 `.env`。

### 低：无 VERSION 文件时构建脚本的 fallback 可能触发未定义变量

版本 fallback 改为使用安全参数展开，保留 Git 描述和 `dev` 两级 fallback。
