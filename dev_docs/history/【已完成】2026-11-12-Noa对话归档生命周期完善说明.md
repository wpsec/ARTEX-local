# 【已完成】Noa 对话归档生命周期完善说明

## 背景

Noa 将平台对话原文归档到 `<dataDir>/noa/chat-conv-<ID>`。平台 transcript、子 Agent transcript 和聊天附件分别保存在 `transcripts/conv-<ID>.jsonl`、`transcripts/conv-<ID>/`、`sessions/conv-<ID>/`。原删除接口只删除 PostgreSQL 对话记录，留下这些可包含对话内容和上传文件的本地数据。

## 实现

- 单条和批量删除先设置会话删除屏障，拒绝新消息、附件上传、旁路追问和新 Agent run；取消当前运行并等待 Agent、已开始的上传及旁路追问结束。
- 将主 transcript、子 Agent transcript、会话工作目录和对应 Noa 归档原子暂存到 `.delete-staging/`。
- 数据库删除失败时恢复暂存文件；成功后清理暂存目录。批量请求中的不存在 ID 不会清理对应路径。
- 暂存清理失败时保留已删除状态，并通过响应 `cleanup_warning` 和服务端日志提示残留清理问题。
- 前端单条与批量删除会显示清理告警。

## Noa 使用建议

Noa 已经具备接入条件并覆盖现有四类 Agent。它的潜在收益是减少长任务重复携带旧历史，同时保留原文供回读；主要代价是额外摘要调用、token 与延迟，以及模型摘要不可靠和归档持续占用磁盘。它仍保持默认关闭。真实模型对照暂缓期间，不把可行性等同于效果已验证。
