# 【已完成；Noa 模型效果评测暂缓】ARTEX 衍生能力借鉴与 Noa 评估

## 结论

- Noa 已通过 `norma/noaadapter` 接入 Planner、Worker、主 Agent 和平台对话。它可用于长上下文任务：当前请求压缩历史，完整原文仍留在归档中供 Agent 回读。技术上可落地，适合作为用户主动开启的实验选项。
- Noa 的摘要由模型生成，可能漏掉或误述细节；压缩时增加模型调用、token 和延迟；原文归档会持续占用磁盘。真实模型效果对照仍按用户此前决定暂缓，所以不能推断它提高了漏洞检出率，也不应默认开启。
- 本轮修复对话删除与 transcript、上传文件及 Noa 归档的生命周期脱节问题。Noa 的默认关闭状态保持不变。
- 衍生能力三项成本收益评审已完成。Judge 故障转人工和一次有界瞬时错误重试、finding 的证据引用匹配状态和可选反证说明已实现，CI/Release 使用的前端构建及应用包构建通过。脚本审批源码快照本轮不做；仅靠 hash 不能绑定实际执行内容，通用 shell 识别与执行端一致性成本高于目前可证明的收益。

## 衍生能力筛选

| 候选能力 | 本地缺口与收益 | 决定 |
|---|---|---|
| BaaRai：POE 等级、证据引用原文匹配、反证记录 | 可帮助审阅者定位支持或反驳结论；可复用已有 traffic snapshot 和 binding version。字符串匹配只证明引用可定位，不证明漏洞成立 | 已实现结构化原文匹配与可选反证；首版不加尚无 ARTEX 稳定定义的 POE 等级 |
| RuoJi6：脚本审批绑定路径、大小、SHA-256 与源码快照 | 让 Judge 看到直接脚本内容有审查价值；但跨解释器、复合 shell 和间接加载很难完整覆盖，hash 本身不保证执行同一字节 | 本轮不实现；待脚本调用数据证明高频且能界定执行绑定范围后再评估 |
| RuoJi6：Judge 故障时转人工、重试及限速 | Judge 默认关闭；原失败默认 `allow`。启用时改为 `ask` 可避免故障静默放行；一次限界重试减少瞬时错误造成的中断。profile 已有共享限速 | 已实现新配置默认 `ask`、保留旧实例与显式设置；瞬时失败至多重试一次，复用 profile 策略，不增加独立限速器 |
| RuoJi6 / sharenjun：基于证据重放请求 | 手动重放可让审阅者基于原始请求调整参数，帮助人工复核特定漏洞 | ARTEX 已有 finding 复测和按授权范围运行的 Agent 工具，但没有交互式请求编辑/重放。手动 Repeater 对自主 Agent 的直接收益有限；新增通用发送入口还需处理目标范围、重定向和 DNS 变化，本轮不迁入 |
| AntiFox：步骤化漏洞报告与流量关联 | 本地已有 finding、流量绑定、复测和报告，整套平台重复度高 | 只借鉴缺失的证据关联规则，不迁移平台架构 |

## Noa 收益与成本

| 方面 | 评估 |
|---|---|
| 可行性 | 已集成到现有 Agent 创建流程，不增加容器、数据库角色或默认工具 |
| 预期收益 | 长任务中减少重复携带的旧对话上下文；完整原文保存在会话归档，可按需取回细节 |
| 主要成本 | 需要额外模型调用生成摘要；增加 token、延迟和磁盘占用；摘要可能丢失因果、参数或授权上下文 |
| 隐私边界 | 归档含原始消息和工具输出，按运行用户限制目录权限，但不加密；删除对话时应连同归档与会话文件一起清除 |
| 决定 | 保持默认关闭。待用户主动运行真实模型对照后，再评估是否扩大推荐范围 |

## 交付边界

- 保持 ARTEX 原生 Agent 入口、名称和交互方式；Noa 仅替换上下文压缩实现。
- 保留对话记录、Noa 归档及上传文件的明确删除语义；数据库删除失败时恢复已暂存文件。
- 不新增默认服务、重型依赖或真实目标评测。
