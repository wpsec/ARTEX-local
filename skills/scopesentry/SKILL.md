# ARTEX 中使用 ScopeSentry

本 Skill 说明如何调用 ARTEX 已配置的 ScopeSentry MCP。不要引导用户配置 Cursor 或其他 MCP 客户端，也不要在对话、命令或报告中索取、读取或输出 API Key。

## 使用前确认

1. 检查 ARTEX 当前 Agent 是否能看到 ScopeSentry MCP 工具。
2. 如果工具不可用，说明 ScopeSentry 服务尚未在 ARTEX 中连接、启用或授权；继续处理不依赖它的部分。
3. 不因 Skill 被调用就自动创建扫描任务。先区分用户要查询已有数据，还是明确要求启动新扫描。

## 查询现有数据

- 用 `list_projects` 或 `list_projects_data` 确认项目及其实际 ID。
- 结合用户指定的项目查询 `list_assets`、`count_assets`；使用工具 schema 中的分页、搜索和过滤参数，不猜测 ScopeSentry 的过滤语法。
- 用 `list_tasks`、`get_task` 查看已有扫描状态；只有需要确认模板或节点时再调用对应查询工具。
- 报告时注明项目、任务和资产来自 ScopeSentry；区分远端记录与本次 ARTEX 测试实际验证的结果。

## 创建扫描任务

创建或运行扫描任务会对目标产生流量。只有用户明确要求启动扫描，且任务目标、授权范围和允许操作清楚时才执行。

1. 核对用户指定的项目、目标、模板、节点和范围限制。
2. 调用查询工具确认所选 ID 与实际目标一致；不得根据域名自行扩展子域、IP 或第三方资产。
3. 使用现有模板和节点。用户未要求时，不创建或修改模板、插件参数、节点或项目设置。
4. 创建任务后记录返回的任务标识，并查询实际状态；任务创建成功不等于扫描已完成。
5. 遇到范围不明、目标不匹配、模板影响未知或服务返回错误时停止该任务操作，说明具体缺口。

## 结果处理

- 只总结与用户目标相关的资产和任务状态，避免复制凭据、个人数据或无关响应内容。
- 区分已完成的远端扫描、仍在运行的任务、失败任务和 ARTEX 本次自行验证的证据。
- 不把 ScopeSentry 中的资产或漏洞条目直接表述为本次已复现的发现；需要复现时按 ARTEX 当前任务范围另行验证。
