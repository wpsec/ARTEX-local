# 交付报告规范

交付报告属于单个漏洞，面向开发修复和业务复核。报告应让接收者看清测试前提、实际操作、业务结果、影响边界和修复办法，并能根据证据重复验证。

报告继续由 `report_finding` 登记漏洞后自动触发的报告 Agent 撰写，与详细报告通过一次 `update_finding_report` 保存。调用方式不变，不增加人工审批步骤。

## 固定报告结构

报告头包含一个一级标题、漏洞名称、单行 CVSS 4.0 信息和有来源的测试时间。正文只使用下列五个二级标题，名称和顺序固定；缺少证据时保留章节，说明缺口。

| 二级标题 | 必需内容与三级标题 |
| --- | --- |
| 描述 | 账号权限、利用前提、受影响接口、实际操作和业务结果。必须包含 `### 定级依据`，说明 CVSS 取值及对应证据。 |
| 修复 | 需要修改的服务端逻辑、位置、机制和预期行为。源码路径、版本或配置未检查时明确标注，不能猜测。 |
| 测试过程 | 必须包含 `### 发现过程与攻击思路` 和 `### 失败尝试与未验证项`；按实际顺序记录验证操作和结果。 |
| 攻击链路 | 用简短树形文本交代初始权限、必要条件、实际操作、系统响应和业务后果。树形内容放在 `text` 代码块内。 |
| 证据说明 | 说明材料来源、采集时间、账号、用途和编号。必须包含 `### Burp 复现` 和 `### 复测标准`。 |

结构示例只规定排版，不代表已经取得证据：

```markdown
# <系统>-<模块> <接口或功能> <缺陷>：<实际复现的业务后果>

漏洞名称：<系统>-<模块> <接口>（<METHOD> <path>）<缺陷>，<必要条件>下可<实际后果>
CVSS 4.0：<完整 Base 向量>  评分 <分>（<等级>）
测试时间：<来自执行或采集记录的时间范围和时区>

## 描述
<权限、条件、操作、业务结果和证据引用>
### 定级依据
<CVSS 各项取值的证据和未验证前提>

## 修复
<具体改动、位置、机制和修复后的行为>

## 测试过程
### 发现过程与攻击思路
<线索来源、怀疑原因、后续操作及判据>
<按实际顺序展开各测试项>
### 失败尝试与未验证项
<实际失败记录、未完成测试、原因及结论限制>

## 攻击链路
<有证据支持的简短树形过程；缺失环节写“未验证”>

## 证据说明
<每份材料的来源、时间、账号、用途和编号>
### Burp 复现
<目标协议、主机、端口、请求取得方式、修改项、发送顺序和判据>
### 复测标准
<正常业务、原攻击步骤和必要边界条件的预期结果>
```

格式校验在工具保存和兼容 HTTP PUT 保存前执行。缺少一级标题、非空漏洞名称或完整 CVSS 向量，章节及必需子节缺失、顺序错误、内容为空，代码块或 HTML 注释未闭合时，保存会返回错误。报告头向量还须与保存参数一致。报告 Agent 应按反馈补齐后重新保存。代码块中的 HTTP 正文不作为报告标题解析。结构校验不证明工具参数、时间或结论真实，仍需核对原始记录。

## 测试记录与结论

每个测试项写清名称、时间和时区、账号权限、前置条件、工具及版本、实际命令或脚本参数、判据、响应和业务结果、结论、证据编号。描述、定级和攻击链的结论应引用对应测试项，避免反复粘贴长命令。

没有复现的结论写“未验证”。未执行、执行失败和未复现分别说明原因；不能把没有测成写成没有问题。失败请求、命令错误、超时和权限拒绝应保留，同类重复失败可以汇总次数并引用代表记录。没有取得失败材料时写“未取得失败尝试记录”，不能补造一次失败。

HTTP 200 不能单独证明业务操作成功。重复提交类问题应分别记录实发请求数、业务成功数、新增记录数和不同记录 ID 数；查询条件保持一致，差分写为测试后数量减去测试前数量。客户端同步放行不能证明服务端同时处理。

## 证据与 Burp 复现

原始材料可能来自 ARTEX 已绑定流量，也可能来自本机 socket、curl、脚本或其他采集记录。必须说明真实来源，不因域名或时间相近便把其他账号的流量作为本次证据。原始请求、响应缺失时说明缺失，不能根据摘要补包。

平台将全部已绑定请求与对应响应成对附在“证据说明”内。每个 `http` 代码块只包含一条留存报文，编号、用途、源流量 ID、请求地址和真实采集时间放在围栏外。报告 Agent 在正文说明证据作用，不重复抄写绑定报文；重存会替换旧的自动附录。

平台留存头部经过采集整理，不等于逐字节网络抓包。为 Burp 整理请求时，应说明 HTTP 版本或传输格式的转换，不能称为原始报文。二进制正文以 Base64 展示时，必须还原字节后才能重放；缺失报文头时也不能声称直接粘贴即可复现。

“Burp 复现”应给出请求来源、目标协议和端口、会话及数据的取得方式、参数修改、发送顺序、并发设置和业务判据。没有实际在 Burp 重放过时注明“Burp 复测未验证”。命令或 curl 不能替代应交付的 HTTP 请求包。

非 HTTP 漏洞仍保留该子节，注明“不适用：非 HTTP”，提供对应工具的完整命令、输入和判据，不为填模板伪造 HTTP 报文。

附包继续执行完整正文长度和哈希校验。绑定报文累计超过 4 MiB、文件缺失或完整性不符时，保存明确失败，不截取片段冒充完整包。更多绑定与导出说明见[漏洞多流量证据](漏洞流量证据.md)。

## 评分、迁移与历史报告

CVSS 向量根据证据填写，权限、用户交互、特殊条件和影响均应给出依据。没有可信计算结果时写“待计算”。详情页根据保存的完整向量在前端本地计算评分和等级，支持新的单行报告头，也兼容旧版三行评分信息。

升级仅替换与已知旧版内置默认内容哈希相同的 Reporter 提示词，并保留用户自定义内容。已有报告不会自动重写；后续重新生成或保存时才应用新规范。格式校验只能约束结构，真实模型的证据选择、措辞和 Burp 实际复现仍需运行验收。
